# Командна розробка: гілки, Pull Request, code review

## Правила

1. **`main` захищена.** Пряме відправлення в `main` заборонене; зміни потрапляють туди лише через PR.
2. **Одна задача — одна гілка.** Назва: `feature/B-xx-коротко` для коду, `docs/B-xx-коротко` для документації, `fix/коротко` для виправлень.
3. **PR від авторки задачі.** Опис за шаблоном (`.github/pull_request_template.md`): яку задачу закриває, як перевірити.
4. **Щонайменше одна ревьюерка, не авторка.** Кожна учасниця за спринт хоча б раз рев'юїть чужий PR.
5. **Рев'ю — у самому PR.** Коментарі до конкретних рядків, питання, пропозиції (Suggested change). Авторка відповідає й виправляє новими комітами в ту саму гілку.
6. **Злиття** — після схвалення (Approve) і зеленого CI, способом *Create a merge commit*; гілку після злиття видаляємо.

## Порядок PR у модулі 2

Задачі залежать одна від одної (усім потрібен каркас, ендпоінтам — авторизація), тому гілки коду створені ланцюжком: кожна наступна відгалужена від попередньої. PR відкриваємо й зливаємо в такому порядку, кожен у `main`:

`B-02 → B-01 → B-03 → B-04 → B-05 → B-06 → B-07 → B-08 → B-11 → B-10`

Після злиття попереднього PR у наступному лишаються тільки його власні зміни. Тому зливаємо через *Create a merge commit*, а не *Squash*: зі squash наступний PR знову показав би чужі коміти. Документаційні гілки `docs/B-12-…` і `docs/B-13-…` відгалужені від `main` напряму, їх можна зливати в будь-який момент.

## Налаштування репозиторію на GitHub (один раз)

1. Створити репозиторій `BloodLink` (через GitHub Desktop: *File → Add local repository* → *Publish repository*), додати учасниць як Collaborators.
2. *Settings → Branches → Add branch ruleset* для `main`:
   - Require a pull request before merging, Required approvals: **1**
   - Dismiss stale approvals when new commits are pushed
   - Require status checks to pass: **build-and-test** (CI з `.github/workflows/ci.yml`)
   - Block force pushes
3. *Settings → General → Pull Requests*: увімкнути *Automatically delete head branches*.

## Щоденний цикл

```bash
git switch main
git pull
git switch -c feature/B-06-centers-by-distance
# ... зміни, тести ...
dotnet test
git add .
git commit -m "B-06: список центрів, відсортований за відстанню"
git push -u origin feature/B-06-centers-by-distance
# далі на GitHub: Compare & pull request → Reviewers → Create pull request
```

Якщо `main` змінилася, поки PR відкритий:

```bash
git switch feature/B-06-centers-by-distance
git pull origin main   # або git rebase origin/main
git push
```

## Що перевіряти під час рев'ю

- Код робить те, що описано в задачі; є тести на нормальний і помилковий випадки.
- Немає секретів у коді (ключі, паролі) — лише в конфігурації середовища.
- Донор не може прочитати чи змінити чужі дані.
- Назви зрозумілі, немає дублювання, публічні методи API мають XML-коментарі для Swagger.
- `dotnet test` зелений, CI зелений.
