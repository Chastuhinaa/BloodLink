# Спринт модуля 2: план і рефлексія

## Мета спринту

Мінімальний робочий прототип: донор реєструється, заповнює профіль, бачить, коли йому можна здавати знову, знаходить найближчий центр і веде історію донацій. Людина, якій потрібна кров, створює запит, а сумісні донори поруч на нього відгукуються. Усе покрито тестами й API-документацією і розроблено через гілки, Pull Request і code review.

## Критерії готовності

- [ ] Демо: «зареєструвався → профіль → коли можна здавати → найближчий центр → запис в історію» працює.
- [ ] Демо: «створив запит на кров → сумісний донор відгукнувся → автор бачить донора й закриває запит» працює.
- [ ] UML-діаграми (use case, класів, послідовності) і схема БД — [uml.md](uml.md), [database.md](database.md).
- [ ] Обґрунтування архітектури та інструментів — [architecture.md](architecture.md).
- [ ] ≥ 20 модульних тестів і журнал результатів — [test-log.md](test-log.md).
- [ ] Інтеграційні тести API і їх результати — [test-log.md](test-log.md).
- [ ] API-документація у Swagger — [api.md](api.md).
- [ ] GitHub: окремі гілки, злиття в `main` тільки через PR, кожен PR схвалює (Approve) ревьюерка, не авторка.
- [ ] Підсумковий звіт і фінальна презентація з демо, планом і рефлексією спринту.

## Сценарій демо (≈ 7 хв)

1. Відкрити <http://localhost:5124>, зареєструватися.
2. Профіль: група A(II) Rh−, стать, дата народження, координати → «Можна здавати вже сьогодні».
3. «Центри»: список від найближчого з відстанню в км.
4. «Історія»: додати донацію сьогоднішньою датою в найближчому центрі.
5. Повернутися в «Профіль»: «Через 90 дн. — з …» (жінка, цільна кров).
6. «Запити» → «Створити запит»: A(II) Rh−, критично, центр «Поділ», телефон. Увійти як донор 0(I) Rh− → «Ваша група підходить» → «Я допоможу» → з'являється телефон. Повернутися до автора → видно донора → «Кров знайдено».
7. Показати Swagger (`/swagger`): Authorize → `GET /api/eligibility`.
8. Показати GitHub: список PR з рев'ю і зелений CI, журнал тестів.
